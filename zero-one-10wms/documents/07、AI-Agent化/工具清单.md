# WMS AI Agent 工具清单 v0.1

> 编制日期：2026-11-23
> 目标：把 `zero-one-10wms` 现有 Java / C++ 微服务能力，整理成 Agent 可直接调用的「工具（Tool）」清单，作为后续 Agent 设计、权限设计与改造排期的基线。
>
> 数据来源（均为代码实证，非推测）：
> - Java：`wms-java` 22 个 Maven 模块的 `Controller` / `wms-apis` Feign 声明（共 150 个接口文件、约 240 个端点）
> - C++：`wms-cpp` 16 个 oat++ 业务服务的 `ENDPOINT` / `API_HANDLER_ENDPOINT*` 宏（约 250 个端点）
> - 路由：`wms-java/wms-gateway/src/main/resources/application.yaml:20-177`
> - 数据：`documents/02、项目需求/数据库/zowms_views.sql`（约 57 个视图）、`zowms_procedures.sql`（6 个存储过程）
> - 前端实际调用：`wms-frontend/src/apis/**`（验证哪些工具已被真实使用）
>
> 说明：当前项目**没有任何 AI/LLM/Agent 框架依赖**，以下均为「裸 HTTP 接口 / DB 视图」，需要在其上包一层 Tool Schema 才能被 Agent 调用。

---

## 0. 工具分级与命名约定

| 级别 | 含义 | 调用策略 |
|---|---|---|
| 🟢 **R（Read）** | 查询/列表/详情/导出/下载，不改数据 | 可直接调用，可缓存 |
| 🟡 **W（Write）** | 增删改/导入/上传/状态变更，一般可回滚 | 允许 Agent 调用，记录审计日志 |
| 🔴 **X（Execute）** | 高风险：批量执行、过账、PLC 指令、批量计费、批量删除 | **必须 human-in-the-loop 二次确认**；建议先 dry-run |

工具 ID 命名：`<域>-<动作>`，例如 `OUT-WAVE-GEN`、`INV-DIFF-POST`。
真实路径按「网关前缀 + Controller 类路径 + 方法路径」拼接；**部分 C++ 端点路径缺少前导 `/`，必须按源码原样拼接**（见第 6 节路由陷阱）。

## 1. 工具总览（按 Agent 任务分层）

| 层级 | 工具类别 | 主要来源 | 代表工具 | Agent 用途 |
|---|---|---|---|---|
| L0 感知 | 库存/效期/看板/每日检查/预警 | j6、j1-dashboard、j3-daycheck、C++ c5-warning、DB 视图 | `STOCK-QUERY`、`EXP-WARN-QUERY`、`DAYCHECK-NOUP` | 巡检 Agent、问数 Agent 的眼睛 |
| L1 作业 | 入库/出库/波次/拣货/下架/复核/回单 | j6、j7、j8-exportmana | `IN-ACCEPT`、`OUT-WAVE-GEN`、`OUT-PICK-QUERY` | 履约调度 Agent、收货上架 Agent |
| L2 决策/执行 | 库内转移/盘点/差异过账/计费 | C++ c3/c4/c5 | `MOVE-BIN-GEN`、`INV-DIFF-POST`、`BILL-CHARGE-BATCH` | 库内优化 Agent、异常处理 Agent（需审批） |
| L3 协同 | 短信/邮件/公告/WebSocket | j2-message/notice/msgmw/ws | `MSG-SMS-SEND`、`NOTICE-UNREAD` | 所有 Agent 的「手臂」 |
| L4 主数据 | 系统/企业/人员/地区/仓库/基础资料配置 | j1~j5、C++ c1/c2/c6/c7/c8 | 各类 `query-all` / `add-*` | Copilot 化（自然语言录入/清洗/审计），不做自主执行 |

## 5. 路由与调用陷阱（务必写进 Tool Schema）

1. **网关缺失的服务/路径**：`/exportmana/**`（j8-exportmana 全部）、`/warningmanagement/**`（C++ 预警）、`/wconfig/**`（c8-wconfig）、`/api/ws/**`（WebSocket）、`/cost-detail/query-cost`（无 `/cost-management` 前缀）、`/file/**`、`/com/deg`、`/pa/list-pa`（c1-persalloc）。这些工具只能直连或补网关路由。
2. **C++ 端点路径缺少前导 `/`**：`stt/stt-on-move`、`pis/upload-pis`、`pis/download-pis`、`pis/batch-delete-pis`、`cost-config/cost-method/query-all`、`ops/download`、`ops/upload`、`chuweiguanli/chuweidingyi/huo-qu-chu-wei-xiang-xi-xin-xi`。拼 URL 时按源码原样。
3. **HTTP 方法与语义不符**：`/gc/export-categories` 实为 POST 上传、`/gc/import-categories` 实为 GET 下载；`/platmanag/def/output`（POST）实为导出；`PUT /kuneiguanli/.../modify-bin-transfer` 前端语义为「生成转移任务」。
4. **鉴权差异**：C++ 接口默认带 `API_HANDLER_AUTH_PARAME`（JWT）；少数导出接口注释掉了鉴权（如 `GoodsDiffPostController.h:92`、`MovingBinController.h:60`）。Agent 需按工具分别处理 token。
5. **状态机约束**：已完成入库通知单禁止修改/删除；已确认的出库任务禁止删除；盘点过账需 `实盘≥账面`。这些约束应在 Tool Schema 的 pre-condition 中显式声明。
6. **SQL 拼接风险**：`ToAcceptServiceImpl`、`ToShelvesServiceImpl` 用字符串拼 `inSql(...)` 做订单类型过滤，仅单引号转义；Agent 批量调用时需限制输入来源。

## 6. 建议的封装优先级
