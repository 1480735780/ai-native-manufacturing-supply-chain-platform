# ADR-022 接口权限声明规范

- 状态：**Accepted（dev 规范，2026-11-26）**
- 范围：Java Controller/API 的权限声明、新增端点静态门禁、公共接口与服务令牌边界、存量迁移与审计
- 关联：ADR-007 认证授权、ADR-017 写操作策略、ADR-021 网关认证与鉴权缺口、`接口权限分组草案.md`
- 明确未做：**未修改数据库、未刷新 `AUTH:RESOURCE_ROLES`、未开启 `deny-unregistered=true`、未提交**

## 1. 背景

ADR-021 实测确认前端 535 个路径中 518 个未登记资源角色，当前 `deny-unregistered=false`，靠 `unregistered-allow-paths` 限制存量前缀。若只靠人工代码评审，后续新增接口会继续产生权限债。本轮先建立“新增端点必须显式声明权限”的开发期门禁，同时把 518 条存量整理为可确认的分组草案；存量角色矩阵与数据库迁移留待单独治理窗口。

## 2. 决策

### 2.1 新增 `@ResourcePermission`

位置：`wms-java/wms-common/src/main/java/com/zeroone/star/project/security/ResourcePermission.java`

```java
@Documented
@Retention(RetentionPolicy.RUNTIME)
@Target({ElementType.TYPE, ElementType.METHOD})
public @interface ResourcePermission {
    String[] roles() default {};
    boolean allowPublic() default false;
}
```

语义：

- 可标注在 Controller/API 类或处理方法；类级是默认声明，方法级覆盖类级。
- `roles` 表示“任一角色即可访问”的角色编码，多个角色是 OR，不是 AND。
- `roles` 不是仓库/租户/本人数据范围；对象级权限仍由业务代码校验。
- `allowPublic=true` 表示拟匿名访问，不得同时声明非空 `roles`。
- 注解是声明与审查契约，**不会自动改数据库、刷缓存或改变网关行为**。运行时仍以网关资源角色配置为准。
- `@PreAuthorize`、`@Secured`、`@RolesAllowed`、`@PermitAll`、`@DenyAll` 是静态门禁认可的等价显式声明，但必须确认 Spring 方法安全在运行时启用；SpEL/角色语义仍需审查。

示例：

```java
@RestController
@RequestMapping("/daycheck")
@ResourcePermission(roles = {"cg", "ckjl"})
public class DaycheckController {

    @GetMapping("/temperature/query")
    public JsonVO<List<TemperatureVO>> query() { /* ... */ }

    @PostMapping("/temperature/add")
    @ResourcePermission(roles = {"ckjl"})
    public JsonVO<String> add() { /* ... */ }
}
```

### 2.2 新增端点静态门禁

脚本：`zero-one-10wms/.dsh-scratch/check-resource-permissions.mjs`

baseline：`zero-one-10wms/.dsh-scratch/resource-permission-baseline.json`

- 扫描 `wms-java/**/src/main/java/**/*.java` 的 `@GetMapping`、`@PostMapping`、`@PutMapping`、`@DeleteMapping`、`@PatchMapping`、`@RequestMapping`。
- 端点身份键为 **HTTP 方法 + 规范化路径**；支持类级前缀、方法级 `value/path`、路径数组、`RequestMethod/HttpMethod` 数组和字符串字面量拼接。
- 当前 baseline：**1097 个 Java 文件 / 349 个端点**，于 2026-11-26 生成；仅豁免扫描时已存在的存量。
- baseline 之外的新端点若没有 `@ResourcePermission` 或等价显式声明，检查失败。
- 重复“方法 + 路径”失败；baseline 中已删除的端点只告警，不阻断。
- `--write-baseline` 是显式人工操作；已有 baseline 必须加 `--force`，`init.sh --quick` **不会自动更新 baseline**。
- 出站 `@FeignClient` 不计入网关入站端点；API 接口上的入站 HTTP 映射纳入扫描。

接入：`init.sh --quick` 固定执行自测和 `--check`；缺少 Node、脚本或 baseline 都失败，不能跳过。

### 2.3 公共接口

只有最小、无业务数据的入口可申请 `allowPublic=true`：

- 健康检查：`/actuator/health`、`/agent/health`；不得暴露 env/heapdump/loggers。
- 验证码：`/captcha/**`；需限流和防滥用。
- 凭证交换：`/auth/oauth/token`、`/login/auth-login`、`/login/refresh-token`；不需要业务角色，但必须校验凭据、签名和过期。

`allowPublic=true` 不会自动加入网关 `white-paths`。变更时必须同步评审网关白名单、下游认证、限流与信息泄露面，并补匿名访问/错误凭据回归。公共接口数量应保持最小，禁止用 `allowPublic` 绕过未完成的资源登记。

### 2.4 服务令牌

- `/login/service-token` 是**机器凭证入口，不是公共接口**：依赖 API Key、IP 白名单和仓库范围，不得声明 `allowPublic=true`。
- 服务令牌 JWT 必须包含 `token_use=agent_service`、`iss=wms-login-agent`、角色与 `warehouse_scope`，短 TTL、可注销；签发方和网关必须一致校验。
- 网关 `service-token-paths` 是白名单：只允许 `/agent/**`、`/login/logout` 和明确列出的巡检只读数据源；清单外一律 403。
- 新增巡检数据源必须同步更新 `service-token-paths` 与 `GatewayAccessFilterTest`，否则扫描会 partial 或取数失败。
- 服务令牌不得访问删除、导出、财务、权限管理或 PLC 执行接口；写操作必须走用户身份与 ADR-017 确认流程。
- Java `@ResourcePermission` 不替代 `token_use`/issuer/仓库范围校验；三层边界必须同时成立。

### 2.5 高危接口

删除、导出/下载、财务、权限管理，以及 PLC 执行等设备指令，必须人工评审：

- 默认最小角色：权限管理仅 `gly`；财务 `cw`；删除/导出按模块 `cg/ckjl`，权限类仅 `gly`；PLC 执行 `ckjl/gly`。
- 禁止 `allowPublic=true`；服务令牌默认禁止。
- 删除需明确对象范围、批量上限、逻辑/物理删除与恢复策略。
- 导出需明确仓库/客户/本人范围、行数上限、文件名/内容脱敏和下载审计。
- 财务需职责分离，资金状态变更与冲销不能由同一低权限角色任意执行。
- 权限管理需记录操作者、目标用户/角色、变更前后差异、时间、来源和结果；关键变更建议双人复核。
- 审计至少包含 `actor_id`、`action`、`object_type/id`、`result`、`timestamp`、`request_id/trace_id`；不得记录令牌、口令或完整敏感请求体。

## 3. 迁移步骤

1. **开发期立即生效**：新增/修改 Java 端点先加 `@ResourcePermission` 或等价声明；`init.sh --quick` 门禁失败时不得合并。
2. **确认分组草案**：先解决 23 条拼接片段、11 条基址/动态模板和 25 条孤儿候选；不得把片段/基址登记成资源。
3. **逐模块补角色矩阵**：按“系统权限 → 财务 → 库存/出入库 → 基础资料/配置 → 其他”排序；每批形成可审查的资源行、角色绑定和回滚 SQL。
4. **数据库与缓存迁移**：在独立窗口执行 `t_s_function`/角色绑定变更，校验 URL 唯一性和 `functiontype=1`，然后调用 oauth2 资源缓存刷新接口；本 ADR 不直接执行这些动作。
5. **运行时回归**：每批至少验证匿名 401、有效角色 200、错误角色 403、未登记路径预期行为、父路径回退、尾斜杠/`;x=1`/重复斜杠归一、服务令牌边界、CORS 与缓存故障 fail-closed。
6. **收敛未登记清单**：每批完成后从 `unregistered-allow-paths` 移除已覆盖前缀；观察业务 403 和调用方兼容性。
7. **最后开启 `deny-unregistered=true`**：只有全部活跃 Java/C++/Python 路径均有明确资源角色或公共/内部例外，且前端、Agent、C++ 回归通过后才允许；当前保持 `false`。
8. **回滚**：先恢复上一批资源行/角色绑定与缓存，再恢复 `unregistered-allow-paths`；不要用自动重建 baseline 掩盖回滚。

## 4. 审计模式

- 每次 `init.sh --quick`：记录扫描文件数、端点数、baseline 数、新增已声明/未声明数、stale 数。
- CI/提交前：查看新增端点 diff，确认声明角色与模块角色一致；高危接口必须有评审记录。
- baseline 更新：必须人工审查 `--write-baseline --force` 的 diff，说明删除/改名/迁移原因；不得为消除红灯盲目刷新。
- 运行时：网关记录认证/授权结果与规范路径，下游记录对象级授权和高危操作审计；日志不输出令牌和敏感正文。
- 定期：对账 Java baseline、前端 `src/apis`、C++ Router、Python Agent 路由与数据库资源行，输出“未登记/孤儿/重复/失效”清单。
- 证据：保存命令、退出码、数量摘要、测试报告和变更单；静态检查通过不等于运行时鉴权通过。

## 6. 已知解析限制

- 这是轻量级词法/括号解析，不是完整 Java AST。路径常量、注解常量、环境变量、SpEL 生成路径、自定义组合映射注解、继承/接口默认映射、动态路由注册无法可靠展开时**失败关闭**，不会静默漏扫。
- `@RequestMapping` 未指定方法时按 `*` 建基线；父类/默认接口映射未展开，后续使用时应显式写方法映射。
- 方法上的 `@PreAuthorize` 等只验证“存在显式声明”，不验证 SpEL 正确性、方法安全是否启用或角色是否真实存在。
- 仅扫描 Java `src/main/java`，不覆盖 C++ Router、Python FastAPI、网关动态路由或前端拼接路径；这些需各自对账。
- 规范化会合并重复斜杠、去尾斜杠、拒绝 `.`/`..` 和 query/fragment；路径参数名保留，因此 `{id}` 改名会被视为新端点。
- baseline 是开发期保护网，不是安全授权；攻击者若同时改源码和 baseline 仍可绕过，必须依赖代码评审、CI 保护和运行时时审计。

## 7. 后果

- 新增 Java 接口从“先上线后补权限”变为“先声明再合并”，权限债不再增长。
- 存量 518 条仍按分组草案治理，数据库与 `deny-unregistered` 不变。
- 注解与 baseline 可被后续工具消费，但当前不自动生成资源行，避免把低置信度推断写入生产权限表。
